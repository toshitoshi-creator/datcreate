# DOT LIFE — 時間と環境で成長するドット生命体

1つのドットから始まり、**現実の1時間ごとに1ドット**ずつ増えていく生命体を観察するゲームです。
形・色・模様は個体ごとに異なり、時間帯・天候が成長に影響します。目・口・手足のような構造は
固定画像ではなく、ドットの積み重ねから「生まれることがある」だけで、抽象的な個体のまま育つこともあります。

- Vite + React + TypeScript / Canvas 2D
- IndexedDB（ドット・履歴）/ localStorage（設定）
- Vitest（ユニット）/ Playwright（E2E）
- 静的ホスティングのみで動作（サーバー不要。`base: './'` なのでサブパスにも配置可）

## 使い方

```bash
npm install
npm run dev        # 開発サーバー（画面左下に DEV 時間送りパネル。開発時のみ）
npm run build      # 型チェック + 本番ビルド → dist/
npm run preview    # ビルドの確認
npm run build:demo # 体験版（⏩ 時間送りボタン付き）を dist-demo/ に出力。本番ビルドには含まれません
npm test           # ユニットテスト
npm run test:e2e   # E2E（本番ビルドに対して実行。Playwright の fake clock で時間を進める）
npm run sim -- 720 16 1   # 開発用: 個体を16体育てて scripts/out/ に一覧PNGを出力
```

### 天気API

既定は APIキー不要の [Open-Meteo](https://open-meteo.com/) です。OpenWeatherMap を使う場合は
`.env.example` を参考に `VITE_OPENWEATHER_API_KEY` を設定してください（ソースには埋め込みません）。
※ `VITE_` 変数はビルド後のJSに含まれ利用者から見えるため、公開して問題ないキーのみ使用してください。

天気は **位置情報を許可した場合のみ** 取得します。座標は約1kmに丸めてメモリ上でだけ使い、保存・表示しません。
拒否・失敗時は天気「不明（中立）」として成長を続けます。

## 仕組み

### 時間
- スロット `i` の時刻 = `startedAt + i時間`。成長数は `floor((now - startedAt)/1h)` と保存済みの
  `lastProcessedGrowthIndex` の差だけで決まり、タイマーは表示更新と「確認」にしか使いません。
- 起動時・復帰時（visibilitychange/focus）に未処理スロットを追いつき生成。120件ずつ別トランザクションで保存し、
  描画は段階的に表示（最大約2.5秒）します。
- 時計の巻き戻し: 何も削除・再生成せず、時刻が最後の処理済みスロットを越えるまで待機（警告表示・記録）。

### 重複防止
- ピクセルIDは `${gameId}:${growthIndex}`、IndexedDB に `[gameId, growthIndex]` と `[gameId, x, y]` の
  ユニークインデックス。
- `appendGrowth` はピクセル追加と `lastProcessedGrowthIndex` 更新を1トランザクションで行い、期待値と異なれば中止。
- 複数タブは `navigator.locks` で排他、さらにDB側の検査で二重生成を防止。

### 生成アルゴリズム（`src/core/`）
- 乱数は `hash32(initialSeed, growthIndex, generatorVersion)` から生成する決定論的PRNG。`Math.random()` は不使用。
- 1. 起点ドットを選ぶ（最近のドット or 全体から / 手足の先端） 2. 周囲の空きセル＋外周サンプルを候補化
  3. 接着度・体のプラン場（個体ごとの楕円の組）・ノイズによる葉状の輪郭・成長方向の慣性・左右対称性・
  穴埋め・環境（時間帯/天候）・顔の傾向でスコア化 4. softmax で確率的に選択 5. 色を決定。
- 形状分析（連結成分・穴・密度ピーク・左右バランス・帯ごとの密度・細い突起・手足方向の先端）は
  決められたエポックごとに再計算してキャッシュ。
- **顔の傾向**: 体が十分に密になった時点で一度だけ（後に確率的に大きなスケールで再計画）、
  目・口の「空いたままになりやすい位置」を体の縁の空きセルに設定。そこを埋める確率を下げるだけで、
  埋まることもあります。既存ドットの移動・削除・色変更は一切しません。強さは設定「生き物らしさの傾向」で調整可。
- 顔らしさへの親和性・手足の傾向・模様・配色は個体の genome により異なり、約2割は顔の傾向を持たない抽象的な個体です。
- 生成済みドットは保存値をそのまま表示し、再生成しません。`GENERATORS` レジストリでバージョン管理し、
  将来の改良は新しい `generatorVersion` として追加します。

### 生成アルゴリズムのバージョン
- 個体は開始時の `generatorVersion` で育ち続けます（途中で切り替えません）。差分は `src/core/tuning.ts` と genome に集約。
- **v1**: 初期版。出力はフィンガープリントテストで固定。v1で始めた個体は今後も同じ規則で成長します。
- **v2**: よりキャラクターらしく（出力は固定済み）。
  - 頭＋胴（大きめの頭）・丸い体など、まとまった輪郭が出やすい。左右対称寄り（非対称な個体も残る）
  - 目の傾向を早め（約36ドット〜）・大きめに。白目＋暗い瞳、目の縁の濃い色、頬の色味（一部の個体）
  - 顔のまわりの色を落ち着かせて読みやすく。環境による1ドット単位の色ぶれ・きらめきを控えめに
  - 手足は短め・太め（2マス幅になりうる）、触手状の放射は減らす
  - 体が大きくなると顔の傾向を大きなスケールで再計画（古い目の穴は自然に埋まることがある）
  - 顔の傾向を持たない抽象的な個体も約1割以上残ります
  - 計測（30個体×720ドット、2つ以上の読める目の空白）: v1 8/30 → v2 17/30

- **v3（新規ゲームの既定）**: 「かわいい」方向に再設計。
  - 丸い体・おもち型・頭＋小さな胴。耳（ねこ耳・うさ耳）や足は体のプラン場の小さな丸い膨らみとして育つ（細い触手状の手足はなし）
  - パステルでほぼ単色の体。天気・時間帯の影響は「やさしい色味の変化」として反映（1ドット単位のきらめきは出さない）
  - 顔は約500ドット時点の体の大きさを見越して、体がまだ届いていない空間に「目・口・頬の傾向」を置く。
    そこに置かれたドットにだけ色（暗い目、白いハイライト、口、ピンクの頬）が付き、成長を妨げない。
    目のまわりが体に囲まれてから塗られるので、早い段階で目が体の縁に張り付かない
  - 目安: 約1週間は顔のない丸い体（やや凹みあり）→ 10日前後で目ができ始め → 2〜3週間で顔が完成。
    その後も成長は続き、体に対して顔は相対的に小さくなる（つぶらな目）
  - 既存ドットの色や位置を後から変えることはしない。約1割は顔の傾向を持たない個体
  - 計測（30個体×720ドット）: 2つの目が完成した個体 29/30、顔の傾向なし 1/30、細い触手 0
- **タイプ（v3）**: 開始時に「かわいい / かっこいい / ランダム」から選択。個体ごとに保存され、途中では変わりません（`GameState.style`）。
  - かわいい: 丸い体・パステル・つぶらな目。約3割は「かわいい・おばけ」（白っぽい体・波打つ裾・黒いだ円の目・ほっぺ）
  - かっこいい: とがった耳、ときどき角やしっぽ、深い寒色系の体、つり上がった光る目、小さな牙。
    約3割は「かっこいい・おばけ」（夜色の体・光るお腹・光る目。赤い目は使わない）
  - **動物**（`GameState.species`）: かわいい・かっこいいの中から、生まれるときに見た目が決まります
    - かわいい: くま・いぬ・ひよこ・かえる・ハムスター・ぶた・ペンギン（＋丸い子・ねこ耳・うさ耳・おばけ）
    - かっこいい: きつね・おおかみ・こうもり・ふくろう・とら・ドラゴン（＋とがり耳の子・おばけ）
    - 輪郭（耳・しっぽ・翼・くちばしの位置など）は体のプラン場の丸い膨らみで、模様（マズル・鼻・お腹・内耳・しま・ほほ）は
      目と同じく「そこに置かれたドットに付く色の傾向」。顔なしの個体もまれに生まれます
    - 計測（各12個体×720ドット）: 目と模様の完成 11〜12/12
    - プレビュー: `scripts/preview-species.sh /tmp/sp "bear fox" "17:720"`
  - ランダム: かわいい・かっこいいのどちらかから、上のどれか
  - どれも「なりやすさ」の傾向で、顔のない個体もまれに生まれます（計測: 各タイプ 29/30 が両目完成）
  - プレビュー: `STYLE=cool PREVIEW_DIR=/tmp/pv PREVIEW=17:720 npx playwright test preview`（STYLE は cute / cool / ghost / ghostCool）
- **何が生まれるかはお楽しみ**: 開始画面の「かわいい / かっこいい / ランダム」は選択肢としてだけ表示。
  生まれた子のタイプ（かわいい・かっこいい・おばけ）や動物名は、育成中・設定・図鑑のどこにも表示しません
  （データには保存され、成長の規則に使われます）
- **完成と図鑑**: 30日（721ドット）で完成。成長はいったん止まり、次を選びます。
  - 「図鑑にしまって、新しい子を育てる」: その子はドット・履歴ごと図鑑に保存され、以後は成長しません。開始画面に戻ります
  - 「このまま育て続ける」: 止まっていた間の時間も含めて成長を再開。あとから設定で図鑑にしまうこともできます
  - 図鑑にしまうときは名前をつける（20文字まで。空欄は不可、ほかの子と同じ名前でもOK。候補「ドット◯号」を自動入力）。
    個体は内部IDで区別するので同名でも別々に保存され、あとから図鑑で名前を変えられる
  - 図鑑では一覧と詳細（名前・ドット数・育てた日数・期間）を表示。図鑑からの削除は確認付き。リセットや読み込みは育成中の子だけに作用します
- **ごはん・あそぶ（アイテム20種）**: 食べ物10種・おもちゃ10種（`src/core/items.ts`）。
  - 使ってもドットは増えない。次の成長（とそれ以降の毎時の成長）がアイテムの分数だけ早まる（`GameState.timeBonusMs`、
    スロット i の時刻 = startedAt − timeBonusMs + i時間）。次の成長が1分後より近くなるようには早めない
  - 在庫は全個体共通（IndexedDB meta）。初回にスターターパック（りんご3・クッキー1・ボール2・ふうせん1）
  - 30日で完成した子から「お礼のプレゼント」（食べ物・おもちゃ・レア各1種、seed から決定）を1回だけもらえる
  - 在庫の減少と成長予定の変更は1トランザクションで保存
- **ステータスと対決**（`src/core/stats.ts`, `battle.ts`, `wild.ts`）
  - ステータスはドットの色だけから決まり、ドットが増えるたびに変わる
    - つよさ＝赤・オレンジ / すばやさ＝黄・緑 / まもり＝青・暗い色 / 運＝紫・ピンク・きらきらした明るい色。この4つの合計は常に100
    - HP・スタミナは体の大きさで伸びて最大200（暖色寄りはHP、寒色寄りはスタミナが少し高い）
  - 対決: 育てている子・図鑑の子 vs やせいのドット（その場で通常ルールで育てた子）。自動のターン制
    （すばやさ＝先手と回避、つよさ／まもり＝ダメージ、運＝会心、攻撃でスタミナ消費・尽きたら休憩）
  - あいては、やせいのドット（「↻ ほかのやせいのドット」で変えられる）
  - 戦う子の選び方: 図鑑の一覧 → 詳細 → 「⚔ このドットで戦う」。スタート画面の「⚔ 対決」は図鑑を「対決させたい子をえらぶ」一覧として開く。
    メイン画面上部の「⚔ 対決」は、いま育てている子がそのまま戦う
- 図鑑は100体以上でも見やすいよう小さめのカードで並べ、サムネイルは画面に入ったものだけ描く
  - 対決は成長に影響しない。1日の最初の勝利でふつうのアイテムを1つもらえる。タイプや動物名は表示しない
- 表示: ドットキャラはゆっくり膨らんだり縮んだり（呼吸）。アイテムを使うと跳ねる／もぐもぐして、アイテムとハートが浮かぶ。
  どちらも表示のみで、アニメーションをオフにすると止まる
- 表示: ドット絵風の1マスの輪郭線（表示のみ。設定でオフ可）
- 見た目の確認用: `PREVIEW_DIR=/tmp/pv PREVIEW=17:250,17:720 npx playwright test preview`（実アプリで個体を描画してスクリーンショット）

### 保存（`src/data/`）
- ストア: `games` / `pixels` / `environment` / `milestones` / `meta`
- `schemaVersion` によるデータ移行の枠組み（`GAME_MIGRATIONS`, `MIGRATIONS`）。新しいバージョンのデータは読み込まず変更もしません。
- エクスポートはJSON。インポートは形式・必須項目・連番・座標重複・色・バージョンを検証してから
  1トランザクションで置換（失敗時は既存データ不変）。

## スマホアプリ（iOS / Android）と完成通知

同じWebアプリを [Capacitor](https://capacitorjs.com/) で包んだアプリ版があります（`android/`, `ios/`, `capacitor.config.ts`）。
アプリ版だけの機能として、**完成したとき（721個目のドット）にプッシュ通知**を出します。

- サーバーは使いません。成長の時刻は開始時刻から計算で決まるので、完成時刻を端末のローカル通知として予約し、
  アプリを閉じていてもOSが通知します（`src/core/notice.ts`, `src/engine/completionNotifier.ts`, `src/services/nativeNotifications.ts`）
- ごはん・あそぶで完成が早まると予約を前倒しし、完成・「このまま育てる」・図鑑にしまう・リセット・設定でオフにしたときは取り消す
- 通知の許可は、最初に予約するとき（育て始めたとき）にたずねる。設定 →「通知」→「完成したらお知らせ」でオン／オフ（Web版には出ない）
- 通知文にはタイプや動物名を出さない（「ドットが完成しました！ お礼のプレゼントが届いています 🎁」）
- Android は端末の状態によって数分ずれることがある（省電力・正確なアラームの許可）。再起動後も予約は復元される

ビルド（Mac / PC で）:

```bash
npm install
npm run app:android   # Android Studio が開く → 実機かエミュレータで実行（Android SDK が必要）
npm run app:ios       # Xcode が開く → 実機かシミュレータで実行（Mac と Xcode が必要）
```

ストアに出す前に `capacitor.config.ts` の `appId`（仮: `app.dotlife.game`）を自分のIDに変え、
アイコン・署名・各ストアの開発者登録（Apple: 年額、Google: 初回のみ）を用意する。

## 画面
- メイン: ドット生命体（Canvas）、ドット数、経過時間、次の成長までの残り時間、時間帯、天気、ズーム(+/−/全体)
  - 1本指ドラッグでパン、ピンチ/ホイールでズーム、ダブルタップで全体表示
- 履歴: 形の変化の記録（その時点のスナップショット付き）／ドットごとの日時・総数・環境
- 設定: 位置情報（天気）、環境の影響、生き物らしさの傾向、アニメーション、サウンド、表示倍率リセット、
  書き出し／読み込み、リセット（確認チェック付き）
